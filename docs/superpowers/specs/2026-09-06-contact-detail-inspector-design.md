# Bearoster 联系人详情与原地编辑设计规范

**日期**：2026-09-06  
**状态**：已通过用户视觉设计确认，待实现计划  
**范围**：macOS `RosterApp` 联系人详情页 `ContactRosterEditor` 及其编辑态  
**不包含**：iOS 联系人页、数据模型、Contacts 同步协议、日历页整体重做

## 1. 产品决定

Bearoster 的主心智是“通讯录管理”，不是日历。默认工作流以联系人列表和联系人详情为中心；生日、标签、工作信息和联系方式都是联系人的属性。日历作为独立浏览工具保留，并复用已确认的轻量网格 + 右侧 Inspector 方向。

联系人详情采用 **B：联系人优先** 的双栏工作台：

- 左侧：联系人列表、搜索、分组和多选。
- 右侧：稳定的 macOS Inspector，负责查看和原地编辑当前联系人。
- 编辑不打开 sheet，不跳离当前联系人；编辑控件在原有信息行内替换。
- 查看态没有底部操作栏；编辑态把“取消 / 完成”放进顶部工具栏。

## 2. 视觉目标

当前页面的主要问题是：居中的 96pt 头像、生日大横幅、多个同等权重的圆角卡片和底部编辑操作共同造成“单调的卡片堆叠”，且不符合宽屏 macOS 应用的 Inspector 语法。

新设计遵循 Apple 的三条原则：

1. **Clarity**：身份、生日、标签、联系方式、工作信息分组清楚；字段标签、值和操作有稳定位置。
2. **Deference**：使用系统背景、细分隔线和克制的语义色，让联系人资料成为视觉主体。
3. **Depth**：使用侧栏、列表、Inspector、工具栏和短状态过渡表达层级，而不是依靠大阴影和装饰卡片。

## 3. 详情查看态

### 3.1 身份头部

将现有居中 hero 改为左对齐身份区：

- 头像：72pt，保持 `ContactAvatarImageView` 和拖拽能力。
- 姓名：22pt、bold、primary。
- 副标题：13pt、secondary，显示联系人组/关系等已有信息。
- 快捷操作：头像与姓名下方的 30pt 圆形按钮，使用系统符号；只呈现已有字段支持的操作，不新增数据能力。
- 详情内容最大宽度：640pt；顶部/左右/底部内边距约为 `28 / 40 / 72`。

### 3.2 生日状态条

生日从全宽彩色 banner 改为低干扰 inline strip：

- 临近生日：透明背景、0.5pt 边框、历法色圆点、粗体倒计时、日期/年龄和小型生日符号。
- 当天生日：使用 `calendarLunar`/现有语义红色的约 8% 浅色背景，红色粗体文字；不使用实心红色大卡片。
- 无生日：虚线 ghost row，文案为“没有生日记录 · 点击工具栏「编辑」可添加”；查看态隐藏空的生日详情组。
- 保留现有 `nextOccurrence`、`daysUntil`、年龄计算和历法数据来源。

### 3.3 信息分组

使用“分组标题 + 一个平面 group box + 行分隔”的结构，替代多张等权 `NativeInfoCard`：

查看态顺序：

1. 生日
2. 标签
3. 联系方式
4. 工作

每组：

- 分组标题：11pt semibold、secondary。
- 容器：约 10pt 圆角、0.5pt 边框、单层极轻阴影。
- 行：最小高度约 38pt，水平 padding 16pt。
- 标签列：84pt，右对齐，13pt secondary。
- 值：13–14pt primary；空值使用 tertiary。
- 分隔线从标签列后开始，避免穿过标签造成视觉噪声。
- 标签使用小型淡色 chip，继续复用标签语义色。
- 生日记录使用现有历法颜色作为紧凑 badge，不给整个组染色。

## 4. 原地编辑态

### 4.1 工具栏

查看态：

- 顶部工具栏显示一个“编辑”主操作。

编辑态：

- “取消”为普通按钮。
- “完成”为唯一蓝色 prominent 主按钮。
- 不保留详情页底部 action bar。
- 取消恢复进入编辑前的 draft；完成复用现有保存逻辑，成功后回到查看态。

### 4.2 行内字段

编辑态保持查看态的同一分组、标签列宽度和行几何；只替换值区域：

- 姓名：姓氏、名字、昵称字段。
- 生日：历法菜单、日期字段、实时计算的“今年生日”只读反馈、添加/删除生日。
- 标签：沿用现有标签编辑入口，不重复实现标签数据逻辑。
- 工作：公司、部门、职位。
- 联系方式：电话、邮箱、地址；复用现有多值字段控件。
- 文本框具有 accent focus ring；placeholder 使用 tertiary。
- 农历等历法特有控件只在对应历法下显示。

编辑态不改变数据层接口。继续使用 `RosterEditDraft`、现有 field views、标签操作和已有保存/错误反馈路径。

## 5. 状态与动效

必须覆盖以下状态：

- 查看态 + 临近生日。
- 查看态 + 当天生日。
- 查看态 + 无生日。
- 编辑态 + 临近生日。
- 编辑态 + 当天生日。
- 编辑态 + 无生日。
- 浅色和深色外观。
- `accessibilityReduceMotion` 开启。

动效：

- 查看/编辑切换使用 `RosterTheme.Motion.quickFade`，约 0.14s ease-out，可带极轻微 scale；减弱动效时只保留 opacity 或不动。
- 按钮按下沿用现有 `press` 反馈，约 0.10s、scale 0.97。
- hover 沿用现有约 0.12s ease-out。
- 不添加持续动画、弹跳动画或装饰性粒子。

## 6. SwiftUI 实施边界

优先改动：

- `Sources/RosterApp/Views/Contacts/ContactsEditorView.swift`
- 必要时小范围改动 `Sources/RosterApp/RosterRootView.swift` 的联系人工具栏状态连接。
- 必要时复用或微调 `Sources/RosterShared/Theme/RosterTheme.swift` 中已有 token；不新增一套颜色系统。
- 文案必须通过 `RosterLocalization` 或已有本地化辅助函数，不写死单语言产品文案。

禁止：

- 不修改 `RosterAppModel` 数据计算和 Contacts 写回协议。
- 不修改 iOS `MobileContactDetailView`。
- 不引入第三方 UI 库、WebView、网页布局或新的依赖。
- 不顺手重做联系人列表、侧栏或日历页；仅保证详情 Inspector 与现有选择状态兼容。
- 不运行 `scripts/update-local-package.sh`，除非用户另行明确授权本地安装。

## 7. 交互与可访问性验收

- 从联系人列表选择联系人后，详情页仍保持稳定，切换联系人不会丢失列表上下文。
- 点击“编辑”后，详情在原位置进入编辑态；不弹 sheet，不改变窗口结构。
- 点击“取消”不写回 Contacts，draft 恢复或丢弃符合现有模型行为。
- 点击“完成”复用现有保存和错误处理；成功后返回查看态，失败时保留编辑内容并显示现有错误反馈。
- 键盘焦点可进入所有输入控件；工具栏主操作有清晰 accessibility label。
- 标签、历法颜色不作为唯一信息编码；文字和结构同时表达状态。
- 浅色、深色、Increase Contrast、Reduce Motion 下文本和控件仍可辨识。
- 现有拖拽联系人行为继续在身份头部工作。

## 8. 验证计划

1. 先运行联系人相关 focused tests，确认改动没有影响编辑 draft、生日计算和标签行为。
2. 运行 `swift build`，确认 macOS target 编译。
3. 如需 `.app` 视觉验证，只做不安装的本地 ad-hoc 构建，使用 `ROSTER_CODESIGN_IDENTITY=-`；不递增版本、不覆盖安装。
4. 用真实 macOS App 验证：查看/编辑切换、取消、完成、保存失败、无生日、深色模式和 Reduce Motion。
5. 保留当前工作区未提交改动，不将无关文件纳入本次 diff。

## 9. 已确认的设计决策

- 用户选择 B 联系人优先作为主方向。
- 用户采纳 C 的日历轻量网格 + 右侧 Inspector 作为后续日历方向。
- 用户明确选择“原地编辑”。
- 用户已确认 `kimi/contact-detail-apple-demo/index.html` 视觉稿可采纳。
- 本规范只冻结联系人详情与编辑页方向，其他页面后续单独设计和确认。
