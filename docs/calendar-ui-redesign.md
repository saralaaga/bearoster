# 日历页 UI 修订方案

**设计日期**: 2026-09-03
**问题区域**: 日历页（`CalendarViews.swift` 的月视图 `MonthGridView` + 当日详情 `DayDetailView`）
**当前状态**: 视觉与结构需要修订，交互问题另见既有动效建议
**适用范围**: 仅 macOS `RosterApp` 的日历页；不涉及 iOS `MobileCalendarView`

---

## 一、诊断：现在为什么"看着不对"

下面每条都对应 `Sources/RosterApp/Views/Calendar/CalendarViews.swift` 里的真实代码，不是主观感受。

### 1.1 选中语言有两套颜色，互相打架 🔴 最主要问题

`CalendarDayCell` 里同时存在两套强调色：

- 今天：`accent`（蓝）圆点 + `accent` 蓝描边（`borderColor` / `background` 里的 `isToday`）
- 选中：`mustard`（黄）描边 + `mustard` 半透明填充（`isSelected` 分支）

结果是：网格里蓝黄两种高亮同时出现，而 App 其它所有地方（侧边栏、列表今日行、倒计时 chip）选中/强调都统一用 `accent` 蓝。日历成了唯一用黄色的页面，视觉上"脱节"，也让人分不清"今天"和"我点的那天"谁更重要。

### 1.2 每个格子都是独立卡片，42 个方框像表格 🔴

`CalendarDayCell` 给每个日期都套了 `cardBackground` 填充 + `separator` 描边 + 圆角 10。一屏 6 行 × 7 列 = 42 个带边框的小方块并排，视觉非常"格子化、表格化"，密度高、呼吸感差。原生日历（Apple 日历、Fantastical）用的是无边框或极细分隔线的网格，让"内容"而不是"格子边框"成为主角。

### 1.3 事件 pill 太重、太吵，还嵌套点击 🟡

`RosterPill`：字号 10、`bold`、纯饱和色块（红/蓝/绿/紫）、圆角 4、白字。问题有三：

- 满饱和实心色块堆在格子里，颜色很"响"，多事件时像贴纸墙
- pill 本身是 `Button`，外层格子也是 `Button` → 点击目标嵌套，点 pill 和点格子行为不同但视觉没区分，容易误触
- 字号 10 + bold 在实心色块上，小屏可读性一般

### 1.4 今天的强调叠了两层 🟡

今天既有"白字 + accent 圆底的日号圆点"，又有"整格 accent 蓝描边"。两层 accent 叠加，强调过头，反而显得脏。原生做法通常只保留一个清晰信号（多是日号那颗圆点）。

### 1.5 格子高度固定 94，空的浪费、满的截断 🟡

`.frame(minHeight: 94)` + 只显示 `occurrences.prefix(2)`。没事件的日子留着一大片空白（大部分格子如此），有 3+ 事件的日子却截断成 "+N"。空间分配和信息密度是反的。

### 1.6 非本月日期做了去饱和，变成灰糊 🟢

`.saturation(inDisplayedMonth ? 1 : 0)` + `.opacity(0.45)`：把上/下月带事件的 pill 直接去色成灰块，既丢了历法配色信息，也不好看。原生一般只降透明度、不去饱和。

### 1.7 星期表头太浅、无周末区分 🟢

表头用 `inkTertiary`（`secondary` 再 ×0.78），偏灰弱、可读性一般；周末（周六日）和工作日没有任何视觉区分。

### 1.8 当日详情标题用了 `.black`（900 字重）🟢

`DayDetailView` 的 `dayTitle` 是 `size: 20, weight: .black`。900 是最重的字重，用在一个 296pt 窄栏的标题上偏突兀，和全 App 其它标题（多为 `.semibold`/`.bold`）不一致。

## 二、修订方案：怎么改

原则：**统一到 App 既有的 accent 蓝语言，把"格子"弱化成"网格"，让事件和日号成为主角。** 不引入新颜色、不引入新设计范式。

### 2.1 统一选中语言（对应 1.1、1.4）✅ 优先级最高

去掉 mustard，全部用 accent：

- **今天**：只保留日号的 accent 蓝实心圆点（白字），**去掉整格蓝描边**。今天靠圆点识别，足够且清晰。
- **选中**：格子用 `accent.opacity(0.10~0.12)` 的淡蓝填充 + `accent` 1.5pt 描边（替换现在的 mustard）。
- **今天且被选中**：淡蓝填充 + accent 描边 + 圆点同时在，三者同色系不打架。

改动点：`CalendarDayCell.background` 和 `borderColor` 两个计算属性，把 `mustard` 换成 `accent`，删掉 `isToday` 的描边分支。

### 2.2 弱化格子边框，改成网格观感（对应 1.2）✅

两个方案，二选一（建议先做 A，改动最小）：

- **方案 A（推荐，低风险）**：默认格子**去掉描边和卡片填充**，只有"选中"和"有事件"的格子才给背景。普通空日子就是透明格，靠 6pt 的 `LazyVGrid` 间距自然分隔。视觉立刻从"表格"变"网格"。
- **方案 B（更彻底）**：整块月网格用极细 hairline 分隔线（横竖 0.5pt `separator`）划分，格子之间无间距、无独立圆角，做成真正的日历网格。改动较大，留到二期。

先做 A。

### 2.3 事件 pill 改轻、去嵌套点击（对应 1.3）✅

- 视觉：从"满饱和实心块"改成"左侧 3pt 竖色条 + 浅色底 + 深色字"，即 `color.opacity(0.14)` 底 + `color` 文字 + 左边一道 `color` 竖条。信息量不变，噪音大幅下降。这和列表页 `StaticKindBadge` 的"淡底深字"是同一套语言，能统一。
- 交互：**pill 不再是独立按钮**，去掉 `RosterPill` 里的 `Button`，整格点击只做"选中这一天"（右侧详情栏会展示当天全部事件并可点进联系人）。消除嵌套点击的歧义。点进联系人的入口保留在右侧 `DayOccurrenceCard`（那里本来就有）。

### 2.4 格子高度自适应（对应 1.5）✅

- 把 `minHeight: 94` 降到 `72` 左右，作为空日子的基准高度。
- 有事件的格子最多显示 2~3 条 pill 后再 "+N"，随内容长高（LazyVGrid 支持行内等高，同行取最高）。整体更紧凑，空白减少。

### 2.5 非本月日期只降透明、不去饱和（对应 1.6）✅

删掉 `.saturation(inDisplayedMonth ? 1 : 0)`，只保留 `.opacity(0.4)`。pill 保留历法配色，视觉更干净。

### 2.6 表头加重、周末区分（对应 1.7）✅

- 表头颜色从 `inkTertiary` 提到 `inkSecondary`（`secondary`），字重 `.semibold` 不变。
- 周末（周六、周日）的日号用 `inkSecondary` 或 `coral` 轻着色，和工作日拉开一点点层次。**幅度要小**，别做成大红大绿。

### 2.7 详情标题字重回归（对应 1.8）✅

`DayDetailView.dayTitle` 从 `.black` 改成 `.bold`（20pt bold）。与全 App 标题体系一致。

## 三、不要动（现在是对的，保持）

- `RosterTheme` 的间距 / 圆角 / 双层阴影 / 语义色刻度——设计系统本身没问题，本次不碰 token 定义。
- 日历配色映射 `color(for:)`（公历蓝、农历红、希伯来紫、伊斯兰绿）——语义正确，保留。
- 右侧 `DayDetailView` 的整体信息结构（标题 + 副标题 + `DayOccurrenceCard` 列表 + 空态卡片）——结构合理，只改标题字重那一处。
- `DayOccurrenceCard` / `RosterOccurrenceCard` 的卡片样式（`cardStyle()` + 头像 + 徽章 + 倒计时）——这些是"内容卡片"，该有边框和阴影，**不要和日历格子混为一谈**。
- 月视图 + 当日详情的左右分栏布局和 296pt 详情宽度——布局合理，保留。
- `contentTransition(.numericText())`、reduce-motion 分支——保留。

---

## 四、禁止做

- 🚫 **禁止引入新配色**。不加渐变格子、不加彩色背景主题、不用 mustard 之外的第三种强调色。整页收敛到 accent + 历法语义色。
- 🚫 **禁止把日历做成"卡片流 / 时间线"等非日历范式**。月视图必须还是标准 7 列月网格，用户心智模型不能变。
- 🚫 **禁止引入任何 Web/Electron/第三方 UI 方案**（AGENTS.md 硬约束），只用 SwiftUI 原生。
- 🚫 **禁止动 iOS 的 `MobileCalendarView`**，本方案只针对 macOS。
- 🚫 **禁止在这一轮顺手改交互动效**（翻月滑动、弹簧等）。那是上一轮的独立议题，混在一起会让 diff 和验收失控。本轮只做静态视觉与结构。
- 🚫 **禁止改数据层 / `RosterAppModel` 的 `visibleMonthDates` 等计算逻辑**。纯视图层改动。

## 五、分期实施建议

按"收益 ÷ 风险"排，建议一期先做红色项：

**一期（改动小、收益最大，先出 demo 给用户确认）**
- 2.1 统一选中语言（去 mustard、去今日双描边）
- 2.3 事件 pill 改轻 + 去嵌套点击
- 2.2 方案 A 弱化格子边框

**二期（视觉细节打磨）**
- 2.4 高度自适应
- 2.5 去饱和改透明
- 2.6 表头 + 周末
- 2.7 标题字重

**三期（可选，风险较高，需再评估）**
- 2.2 方案 B 真·网格 hairline

## 六、验收标准

- [ ] 日历页除历法语义色外，只出现 accent 蓝一种强调色，无 mustard
- [ ] "今天"和"选中日"同色系、可区分、不叠加双重描边
- [ ] 空日子无边框卡片感，整屏从"表格"变"网格"
- [ ] 事件 pill 为淡底深字 + 竖色条，点击格子只选中当天、无嵌套按钮歧义
- [ ] 非本月日期保留历法配色（不灰糊），仅透明度降低
- [ ] 深色 / 浅色模式都验证过，对比度达标
- [ ] reduce-motion 下无异常
- [ ] `scripts/update-local-package.sh` 通过，实机截图对比 before/after
